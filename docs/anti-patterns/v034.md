# FanUI V0.3.4 Anti-patterns — Mobile Precision

These failures apply after the main responsive transformation is already structurally correct.

## Double-decker Mobile Header

A phone header keeps Brand/CTA on the first row and the full desktop primary navigation as a second permanent row.

**Why it fails:** persistent chrome consumes too much of the first viewport and treats Mobile as a compressed desktop.

**Prefer:** one primary row plus a menu/drawer.

## Truncated Sidebar Replacement

A complex sidebar is replaced by a short horizontal chip strip exposing only a few sections.

**Why it fails:** the user loses the original information architecture and cannot reach secondary areas predictably.

**Prefer:** a drawer, sheet, selector, or other complete replacement path.

## Editorial-sized Documentation

Docs use oversized headings/body spacing that belongs to a Blog or Marketing page.

**Why it fails:** task reading becomes slow and vertical progress collapses.

**Prefer:** the dedicated Docs mobile type scale.

## Wrapped Code Semantics

Shell commands, JSON, configuration, or code are line-wrapped simply to avoid any horizontal movement.

**Why it fails:** code structure becomes harder to scan or copy correctly.

**Prefer:** preserve code formatting and use local horizontal scrolling.

## Multi-row Category / Tab Collapse

A single-line category or tab strip wraps into two or more rows at narrow widths.

**Why it fails:** navigation chrome becomes unstable and consumes unpredictable height.

**Prefer:** intentional local horizontal scrolling, collapse, or replacement.

## Tiny Icon Target

An icon-only control exposes only the 14–18px SVG as the clickable target.

**Why it fails:** it is difficult to hit and visually inconsistent with touch UI.

**Prefer:** 40–44px control geometry with the glyph centered inside.

## Mobile Icon Regression

Desktop icon semantics and alignment are correct, but mobile CSS changes display, line-height, margin, stroke, or centering.

**Why it fails:** component precision is not breakpoint-specific; the same semantic control should remain trustworthy at every width.

**Prefer:** explicit icon-box selectors and rendered verification at phone widths.

## Header Collision at 375px

Brand, CTA, menu, project selector, or icon controls technically fit at 390px but collide or truncate unpredictably at 375px.

**Why it fails:** 390px is not a sufficient minimum pressure test.

**Prefer:** explicit 375×812 acceptance.

## Nested Control Escape

A child option inside a segmented control, tab capsule, compact selector, or similar nested control is given a minimum/fixed height that is equal to or larger than the **outer** track height without subtracting the track's border and padding. The selected option then protrudes outside the container, breaks radius continuity, or looks vertically misaligned.

**Why it fails:** touch-target rules were applied to the child in isolation instead of reasoning about parent inner-box geometry. `44px parent + padding + 40/44px child` is not automatically valid.

**Prefer:** define the geometry from the outside in:

```text
outer track height
− border
− vertical padding
= maximum visual child height
```

For example, a 44px segmented track with 1px border and 3px vertical padding has roughly 36px of inner visual height. Keep the child inside that box, and provide larger interaction geometry separately when necessary.

Hard rule:

> A nested selected state must never visually escape its parent track to satisfy a generic touch-target minimum.

## Whole-page Overflow Hidden by `overflow-x: hidden`

The page uses global overflow clipping to conceal an actually-overwide child.

**Why it fails:** content may be inaccessible even though no scrollbar is visible.

**Prefer:** fix the overwide region and allow only intentional local scrolling.

## Completion rule

A Mobile surface fails V0.3.4 if any of these remain on a primary route, even when the overall responsive score is otherwise high.
